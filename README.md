# القرآن الكريم — iPhone web app

Static PWA: open it in Safari → Share → **Add to Home Screen**. It must be served over HTTPS
(GitHub Pages, Netlify, Cloudflare Pages…) for offline support; any static host works.

- **Hafs** is drawn exactly like the 1441 Madani print with the KFGQPC QCF V2 per-page fonts
  (loaded from verses.quran.foundation as pages open, then cached offline).
- **Mushaf pages**: 604 pages × 15 lines, KFGQPC Uthmanic fonts and text for 8 riwayat
  (Hafs, Shu'bah, Warsh, Qalun, al-Duri, al-Susi, al-Bazzi, Qunbul), each with its own
  orthography, pause and rub' marks.
- **Landscape**: type fills the width and the page scrolls vertically.
- **On a computer** (a mouse, a window at least 900 px wide; `?desk` in the address asks for it
  anyway): the mushaf lies open, two facing pages as tall as the window (or one: `1` / `2`), the
  type made larger or smaller (`+` `−` `0`, Ctrl + wheel); a bar along the top with the search
  (`/`), a rail of the panels, the panel chosen and the tafsir standing beside the pages, a line
  under them to run through the mushaf by. The wheel and the arrow keys turn the pages, `↓` `↑`
  choose an aya, a click or the right button opens its card beside it, two clicks a word's;
  `?` lists every key. All of it is `desk.js` and `desk.css`, under `body.desk`.
- **Search**: surah names (Arabic/English, fuzzy), aya text (fuzzy, diacritics-insensitive),
  `2:255`, `البقرة ٢٥٥`, `baqara 255`, page numbers. Best match first; Enter jumps to it.
- **Tafsir As-Sa'di** per aya (data/tafsir/<surah>.json, from spa5k/tafsir_api), downloadable for offline.
- **Adhkar** (الأذكار): every chapter of Hisn al-Muslim (Sa'id al-Qahtani), text from the official
  hisnmuslim.com edition with each dhikr's source; morning, evening, after-prayer, sleep and waking
  adhkar are split one per card with their counts. Tap to count, swipe to move on, hold to finish one.
  Quranic passages use the KFGQPC Uthmani text; the rest is set in Amiri (SIL OFL).
  `data/adhkar.json` is built by `tools/adhkar.py` (see its docstring).
- **Offline**: Settings → «تحميل الكل» saves the mushaf, tafsir, adhkar and (optionally) the recitation.
- **Audio**: every riwaya is recited by a reciter of that riwaya, played continuously with
  page follow and the aya highlighted:

  | Riwaya | Reciter | Source |
  |---|---|---|
  | Hafs | Yasser Al-Dosari | everyayah.com, one file per aya |
  | Shu'bah | Ali Al-Hudhaifi | mp3quran.net, read 305 |
  | Warsh | Omar Al-Qazabri | mp3quran.net, read 80 |
  | Qalun | Mahmoud Khalil Al-Husary | mp3quran.net, read 270 |
  | al-Duri | Mahmoud Khalil Al-Husary | mp3quran.net, read 269 |
  | al-Susi | Abdul Rashid Sufi | mp3quran.net, read 65 |
  | al-Bazzi | Okasha Kameny | mp3quran.net, read 296 |
  | Qunbul | Ahmad Deban | mp3quran.net (no published timing: aligned by `tools/align.py`) |

  mp3quran.net has one file per surah. `data/audio/<riwaya>.json` gives, in the riwaya's own
  count, when each aya starts (mp3quran.net's `ayat_timing`). The files are constant bitrate,
  so the app reads each aya with an HTTP range and joins the frames. Settings → the recitation
  card saves the current riwaya's recitation for offline use (1.3–3.3 GB a riwaya).

## Data

`data/*.json` is generated by `tools/build.py` from
[quran-data-kfgqpc](https://github.com/thetruetruth/quran-data-kfgqpc) (text, fonts, per-aya
page/line) plus quran.com v4 (`verses/by_page`, used for surah metadata and rub' al-hizb numbers).
KFGQPC gives only the first and last line of each aya, so word-level line breaks are solved
with a DP that balances line widths measured with HarfBuzz in each riwaya's font.

Run it with `uharfbuzz` installed; it expects the cloned repo in `dl/`, the quran.com pages in
`qcom/<page>.json` and `chapters.json` next to the script, and writes to the given directory:

    python3 tools/build.py data

`data/audio/` (when each aya starts in the recitations) is built by `tools/recitations.py`: it
reads mp3quran.net's `ayat_timing` for each reciter, checks every surah against the riwaya's
count of ayat in `data/<riwaya>.json` and the files' sizes. Qunbul's timing is first worked out
by `tools/align.py` (curl, ffmpeg, numpy, numba, librosa) from Ahmad Deban's recording and
Okasha Kameny's timed al-Bazzi:

    python3 tools/align.py data/audio/bazzi.json data/audio/qumbul.json
    python3 tools/recitations.py data

`data/words/` (the word card: a long press on a word, Hafs) is generated by `tools/words.py` from the
[Quranpedia.net](https://quranpedia.net/dumps) dumps, version 2026-10-31: `meanings.json.gz`
(word meanings from four books of غريب القرآن: السراج في بيان غريب القرآن, كلمات القرآن,
تذكرة الأريب, التبيان في تفسير غريب القرآن) and `morphology.json.gz` (roots, lemmas and grammar from
the [Quranic Arabic Corpus](https://corpus.quran.com), GNU GPL). Republished here with credit to
Quranpedia.net and the dump's version, as its license asks.

    python3 tools/words.py data/hafs.json meanings.json.gz morphology.json.gz data/words
